# ai-sdlc：从第一个任务开始

让 AI 在项目中按目标实施、用真实检查验证结果，并在下次会话接着做。面向个人开发者与一人公司，适合持续迭代、已有工程约束的项目；一次性问答或小修改通常不需要先接入整套机制。

这份文件给使用者看；[SKILL.md](SKILL.md)是 AI 的执行入口。安装只提供能力，不会自动接入项目、启用 hooks 或修改代码。

## 准备条件

| 使用方式 | 需要什么 |
|---|---|
| 阅读规则、采用文档模式 | 能读取本地 Skill 的 Codex；项目已有的验证工具 |
| 使用随包执行器和自检 | Python 3.10+，仅标准库；不要求最新 Python 或本开发仓库的私有环境 |
| 可选 Git 对象检查 | Git；项目现有等效保护可继续复用 |

核心脚本目标兼容 macOS/Linux；实际测试范围见[版本说明](CHANGELOG.md)。本文安装命令面向 macOS/Linux shell，不承诺 Windows 或所有 AI 客户端已验证。仅文档模式不要求运行 harness，但项目自身的测试仍可能需要 Python 或其他环境。

## 安装并确认发现

首次建议只装到一个项目。准备来自维护者或[分发仓库](https://github.com/Odinary-AI/ai-sdlc)的完整包，记录下载提交或交付身份；解压后根目录应有 `SKILL.md`、`agents`、`references`、`scripts`、`assets`。不要只复制 SKILL.md，不把开发仓库整体当成 Skill。

在目标项目根目录打开终端，将 `AI_SDLC_SOURCE` 设为已解压的包根目录绝对路径，再执行以下代码。目标已存在时会停止；不要直接覆盖已有安装或本地修改。

```sh
set -eu
: "${AI_SDLC_SOURCE:?请先设置完整包的绝对路径}"
test -f "$AI_SDLC_SOURCE/SKILL.md"
test -f "$AI_SDLC_SOURCE/scripts/harness.py"
if test -e .agents/skills/ai-sdlc || test -L .agents/skills/ai-sdlc; then
  printf '%s\n' 'ai-sdlc 已存在，请先比较版本和本地修改。' >&2
  exit 1
fi
mkdir -p .agents/skills
cp -R "$AI_SDLC_SOURCE" .agents/skills/ai-sdlc
```

项目级 `.agents/skills` 来自[Codex 官方说明](https://learn.chatgpt.com/docs/customization/overview#skills)（2026-11-10核对）。已有用户级安装可继续使用，不必再复制一份；同名副本应先确认实际加载路径。当前提供普通 Skill 文件包，不提供一键安装器或插件安装包。

在 Codex 打开这个项目并开始新会话，确认可用 Skill 中出现 `ai-sdlc`。然后输入：

> 使用 $ai-sdlc，只读核对当前项目。告诉我实际读取的 Skill 路径和版本、当前项目入口，以及是否已经接入。先不创建或修改文件。

应能定位真实的 SKILL.md、版本和项目状态。AI 只说“已安装”不够；结合客户端的 Skill 发现结果和实际文件路径核对。不同客户端版本的刷新方式可能不同；未出现时先检查目录层级、同名副本和客户端支持，必要时重新打开项目。文件复制成功不证明当前会话已加载。 本轮在 macOS 上用 Codex CLI 0.167.0-alpha.3.2 的原生 `skills/list` 核对了临时项目目录，发现结果为 repo 且 enabled；未据此声称桌面当前会话已加载或真人使用通过。

## 开始第一个任务

先用[首任务教程](examples/first-task/README.md)在临时目录练习，体验测试失败、修复、证据保存和恢复，不碰真实业务项目。

准备接入真实项目时，可输入：

> 使用 $ai-sdlc，接入当前项目。先核对已有规则、测试和未提交修改，说明适合沿用文档模式还是脚本模式，以及预计新增或更新的文件；复用现有规范，保护已有修改。目标是完成一个小任务并能在新会话恢复。范围不清或需要我决定时再问我。

AI 应按[接入流程](references/adoption.md)准备实际映射和检查，用户负责目标及必要取舍，不需要先手写通用 JSON。不要把练习项目的需求、检查或授权原样搬进业务项目。

两种模式已由[任务流程](references/lifecycle.md#模式与生效边界)定义：已有记录与验证足够时可用文档模式；确需自动核对证据及交付条件时采用脚本模式。安装、新项目接入和每次任务执行是不同动作。首次不必启用 hooks 或开展全面治理，也不能为了轻量而漏掉项目本来必需的验证。

## 怎么判断进展

- **已安装**：完整文件位于客户端可发现的位置，并核对实际加载路径。
- **已接入**：现行规则、目标、验证与状态来源明确，必要内容已填实，完成最小任务试用。`doctor` 就绪只证明机械检查满足，不替代内容审阅。
- **任务已完成**：当前范围的必要检查、证据和审阅满足，尚需人的验收已按要求处理；不能只看文件存在或 AI 的完成回复。

脚本模式可按[诊断与验收接口](references/cli.md#诊断与验收视图)查看缺口；文档模式直接核对任务和实际检查结果。

## 常见问题

| 看到什么 | 下一步 |
|---|---|
| 找不到 `$ai-sdlc` | 检查项目根、`.agents/skills/ai-sdlc/SKILL.md` 层级、同名副本及客户端发现状态；不要重复嵌套复制目录 |
| Python 缺失或过旧 | 先核对实际 `python3 --version`；使用满足 3.10+ 的解释器，并确保检查子进程一致；不要求升级整机 |
| `doctor` 报占位内容、缺文件或链接 | 让 AI 读取具体缺口，补真实项目内容；复制模板本身不算接入完成 |
| 测试通过却不能关闭任务 | 按 `resume` 的当前缺口核对证据是否失效、最新检查是否失败，以及审阅或人工验收是否缺失；不挑旧成功或手改完成状态 |
| 新会话不知道下一步 | 显式调用 Skill，从项目入口和状态恢复；脚本模式读取 `resume`，不要重新初始化覆盖已有配置 |

若要确认包脚本可执行，可选运行 `python3 /实际包路径/scripts/self_test.py`。它只在临时项目做机制自检，不能证明你的项目已接入或产品正确。遇到问题反馈实际版本、命令、错误和脱敏的最小复现，不提交私密项目文件或凭据。

## 升级、退出与版本

先读[用户变更](CHANGELOG.md)，再比较新旧包与本地修改并保留旧副本；核对项目中引用的脚本路径及当前证据，不用重新 adopt 覆盖配置。`dev` 是预览版本，试用时固定具体提交或交付身份，不把浮动 main 当成不可变版本。包内版本不证明安装或远端发布状态。

停用调用不会删除项目已采纳的规则。卸载前核对项目检查及 hooks 是否引用包路径，再将包移出发现目录并保留备份；任务和证据不随之删除。升级及旧名称迁移详见[接入说明](references/adoption.md)，平台 hooks 的退出沿[适配说明](references/codex-hooks.md)。
