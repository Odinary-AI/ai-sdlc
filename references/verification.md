# 验证与交付边界

比例验证由项目现行验证策略决定。先定向，再受影响消费者/流程回归；仅跨模块公共契约变化、依赖面经检查仍不能界定、正式发布或结项明确要求，或项目现行策略另有要求时选择全量。局部公共契约变化先核对实际消费者，不仅因接口是公共的就全量。缺环境和跳过明确列出，不降低必需要求求通过。

首次采用检查命令、相关命令或配置变化，或有副作用疑点时，按风险核对输出、覆盖、清理和持久状态写入。历史证据作为输入时按只读使用，新输出不得默认覆盖原件；调整路径时核对实际写入目标及产物消费者，避免误写受保护输入或使引用失效。正常重复运行可复用仍有效的核对，固定的可再生产物可按项目约定更新。

分别判断命令执行结果、实际覆盖及未覆盖项、证据有效性和任务验收是否满足。退出成功不代表测试有效或必需覆盖齐全；跳过是否阻塞任务取决于现行验证策略与任务验收映射，必需项缺失仍阻塞。非必需范围有既定依据，跳过事实及结论限制仍保留，不能见到失败或缺环境后改称可选来取得通过。

缺陷修复以已确认的预期行为和原始复现为依据。实现与测试同时变化时，在现有差异审阅中核对断言、输入、模拟和跳过条件是否削弱原有保护，不能仅凭修改后的测试通过认定缺陷已修复。测试确有错误或需求已按授权变化时可以修改，须说明依据，并保留对仍然有效的失败场景的覆盖；相关旧证据按下述规则重新核对。

## 任务测试设计与证据深度

实施前从任务验收和现行行为契约确定：要证明的可观察结果与不可退化约束，直接影响本次结论的错误和边界；为所选风险安排能检出错误的输入或故障顺序、预期结果、观察位置及检查入口。说明验证时机、相关变化后的重验范围，以及任务内结束条件与未覆盖处。已有验收、项目验证策略和有效检查可直接引用；简小改动可在任务记录合写几行，不另建测试计划或必填矩阵。

验证**范围**按本页比例规则选定向、受影响回归或有触发依据的全量；验证**深度**按失败后果与结论依赖的边界选择。普通行为核对正常结果及有影响的错误、边界和消费者。并发、持久化、权限、迁移或外部副作用相关时，仅对本次受影响的关键状态转换、竞态顺序、故障后状态或恢复选择可证伪检查；声称真实数据库、文件、进程、权限或服务边界成立时，证据须经过相应边界，纯模拟结果不能替代。是否需要单元、集成、故障注入或真实环境观察由所声称结果决定，不因风险类别名称自动升级全量或高成本验证。

例如，仅修改不改变行为的说明文字，可核对实际差异、引用和受影响呈现；没有相关风险时不机械增测。若任务改动跨会话恢复及并发子任务写入，则可按项目契约选择“任务已提交后断连并重开”“未完成时重复恢复”等顺序，观察持久状态和重新进入后的实际行为，核对进度、去重及并发上限等适用约束；具体场景和数值取自项目，不由示例设定。

充分的证据须让已识别的关键风险可能被检查否定，经过结论所需的实际边界，适用检查门通过，且对象、输入和结果仍有效；剩余局限要明确。用例数量、覆盖率、构建成功或多个代理意见不能单独代表完成。高成本检查应对应具名结论或会影响的决定；缺必要环境、授权或预算时保留未验证及影响，不缩小既定必需验收来取得通过。

## 采证前确认观察对象

采集验收证据或执行依赖动作前，核对实际对象、当前状态及必要前置条件与目标一致。按任务选择能区分目标与相似对象的信号，例如页面身份与目标内容、测试数据归属、服务端点与运行版本、文件实际路径；命令参数、通用文案或产物文件名不能单独证明实际命中目标。确认应对应采证或动作发生时的对象，切换、重载或相关状态变化后重核受影响部分，不规定统一选择器或等待时间。

前置失败、对象不符或状态尚未就绪时，停止依赖该条件的动作，保留观察并修复或报告缺口；不得改用默认对象或其他对象后仍宣称原目标已验证。例如截图成功但实际停在另一页面，图片有效也不能支持目标页面的验收。已有可靠的对象确认可复用，不要求为每次观察新建报告。

## 条件预检与消费者核对示例

依赖、安装契约或新增测试变化时，可先用现有命令检查受影响的最小前置：例如依赖包实际入口是否存在、安装步骤是否仍生成所需文件、新测试能否被发现并执行一个代表用例，再安排完整基线或受影响复验。前置不成立先定位，保留失败；预检不能替代既定必需测试。完整基线仍可用于归因与退化对照；没有可比测量不宣称预检已节省时间。无相关变化、已有可靠依据时不新增此步骤。

消费者核对可从实际注册入口列出变更对象，再对应诊断、权限与验证的实际消费者，双向检查遗漏与已退役引用。例如新增命令后核对诊断是否能识别它、权限是否覆盖真实执行入口、测试是否执行该入口；按项目已有实现判断，不要求统一注册表、白名单或全仓固定扫描。

## 从行为选择验证场景

涉及异步、多阶段、可重试或部分成功的关键操作时，从现行行为契约和实际执行阶段推导代表场景，再对应已有检查。按需要辨别：哪一步已经产生副作用、哪一步的结果仍未知；失败后哪些输入或状态应保留/重置；重试、继续或撤销在何时才可执行。已有等效分析直接复用；只记录影响验收的场景及选择依据，不要求每项任务建立状态矩阵或穷举故障组合。

例如“保存记录→刷新列表”应分别核对保存失败、保存成功但刷新失败，以及已有数据在重读尚未结束时的可操作状态。刷新失败不能直接解释为未保存；是否可重放写入取决于幂等或去重契约，结果未知时先核对已发生的效果。示例用于识别阶段边界，不要求所有项目实现相同按钮、事务或恢复方案。既有测试全部通过只证明已测场景；漏掉当前验收依赖的阶段时补验，不用清单齐全替代选择依据。

验收涉及一致、对齐、同步、对应或守恒时，明确比较对象、共同约束及允许差异，并观察对象之间的关系；各对象分别合规不能代替关系成立。例如同组控件尺寸各自合规仍可能错位，两端数据各自格式正确仍可能版本不对应。比较采用共同坐标、时间点、版本或业务口径等适用条件，阈值与例外取自项目现行标准；缺少影响验收的依据时先补齐或列缺口，不自创通用阈值。按风险选择关系偏差及合法差异的对照，复用几何、契约断言、实际观察或等效方法，不要求所有关系自动化。

## 自建检查器接入与校准

新增或改变检查器、结果适配或汇总判定时，明确其成功信号与交付声明的对应：进程结束、输出有效、必需范围完成和验收满足分别判断。存在报告或产物协议时，核对它属于本次执行、结构完整且结果满足要求；缺失、损坏、提前退出或误用旧成功输出不能解释为通过。优先使用现有测试框架、适配器及执行器；没有报告协议的普通命令可沿其可靠退出契约，不强制增加JSON、计数或第二套执行器。

按相关失败方式在隔离环境校准：例如退出0但缺报告、报告失败而进程退出0、未执行完却正常退出、残留旧报告、产物有效但观察对象错误、超时，以及合法成功。只补现有保护未覆盖且会影响本次判定的反例，已有有效校准可复用。选择本次唯一输出位置或验证执行身份均可；文件存在本身不能证明新执行完成，对象对应仍按[采证前确认](#采证前确认观察对象)核对。真实未完成/失败不得通过删记录、过滤坏结果或换检查类别消除。

脚本模式的tests检查继续使用[现有计数协议与自检](cli.md#可移植机制自检)；文档模式由项目命令、适配器及开发AI核对同样的证据边界，不要求接入RUN，也不宣称自动阻断。工具只能验证所映射的信号，不能据此推断场景完整或用户接受。

## 条件执行示例

当下一动作依赖检查成功时，应先取得并核对检查结果，再执行依赖动作；可通过程序条件或分次工具调用实现。顺序排列、等待命令返回或批量提交两个工具调用本身均不保证失败时停止。需要报告/产物的检查须先完成上节判定，不能仅凭外层退出0继续。独立工作仍可并行。

下面仅演示已具备可靠退出契约的本地检查与打包衔接：check.py应先校验自身必需输出，失败或未知返回非零；package.py代表已授权的后续动作。项目可换用自己的命令，不将此示例作为新执行器或所有任务的必经步骤。

```python
# example: checked-followup
import subprocess
import sys

subprocess.run([sys.executable, "check.py"], check=True)
subprocess.run([sys.executable, "package.py"], check=True)
```

检查失败时保留结果，修复或核对后仅重验受影响范围。后续动作已经发起但结果未知时先检查现场，不盲目重放；检查通过也不授予发布、删除或其他尚未获得的权限。

## 测试集维护

行为或风险变化时，由开发AI核对已有保护，按缺口新增或更新测试；接口、数据格式及消费者变化时检查适用的契约、历史数据夹具和集成路径。严重或容易复发的缺陷优先把原始复现转为持久回归保护，在安全隔离条件下证明能识别原缺陷；无法重现旧状态时说明替代证据及限制，不伪造修复前失败。测试预期来自现行需求、规则或独立参考结果，不能只复制当前实现。已有保护充分、低影响且可逆的修改无需机械增测。

测试持续变慢、不稳定、重复或与已授权需求不符时，定位原因后修复、合并或退役；说明仍有效行为由何处保护，保留失败事实。不靠重跑到通过或静默跳过掩盖不稳定，必需覆盖缺口仍按原策略处置。选择器、夹具或检查命令变化后同步项目验证映射并验证实际覆盖，测试数量或覆盖率增长不等于保护增强。缺陷修复和测试维护沿用任务记录，不另建测试台账。

## 性能、容量与运行费用

数据规模、查询或批处理、并发/重试、付费调用路径发生相关变化，或出现延迟、资源与费用退化信号时，先判断现有证据是否足以支持本次结果；阶段检查也核对相关累积变化。资源安全限制与实验成本不能代替正常负载下的产品表现。无相关变化或已有证据仍充分时不追加测量，不能仅按代码行数、改动大小或固定频率要求压测。

复用项目已有使用规模、性能要求、资源/费用预算及检查，选择能暴露本次风险的最小代表负载或边界场景，按需观察延迟、吞吐、内存、I/O、实际调用次数或运行费用；不是每项指标都必测。新数据访问路径、全量加载、扇出、重试放大等按实际能力追踪到消费者，功能正确与规模/费用可接受分别判断。没有既定阈值时可在授权内建立基线、识别明显退化；基线不自动成为合格标准，不擅设承诺或用相对改善证明绝对容量足够。缺少影响当前验收的标准、环境或预算时记录缺口，按现行边界处理，不能写通过。

优先复用现有测试、探针及运行数据；比较时核对版本、配置、数据量/分布、并发及缓存等相关条件，保留原始观察、适用基线和未覆盖范围。估算费用与实际消耗分开，缺用量不填零，小样本不外推生产容量。测量保留授权、隔离和成本上限，不因本规则自动发起生产压测或付费调用；发现退化后定位原因，修复时同时保护功能正确性。项目的标准、代表规模、指标与命令归现有TESTING或等效来源，结果归任务，不建立默认性能平台、独立专项或全任务必填表。

## 执行证据与交付

证据保留以可追溯的原始记录及其必要依赖为准。已有任务记录、持久RUN和交付回执时，其他位置引用其路径，不默认再保存完整返回或摘要副本。begin/update等中间规格可放临时目录；只有包含持久记录未覆盖、且对复核或恢复有用的信息时才作为附件保留。工具契约要求的日志、摘要、报告及校验文件仍完整保留；唯一的失败或恢复依据不能当作重复材料丢弃。此约定指导新增记录，历史清理仍按项目保留要求及授权处理。

脚本模式所选 tests 检查的报告范围均按必需测试处理，任何跳过都不通过。接入混合必需与可选范围的套件时，优先按项目已有选择能力将必需范围映射为独立检查，记录选择依据及未纳入范围；计数必须来自实际执行，其他运行记录保留。无法可靠分离时列为适配缺口，不过滤坏回执、改写计数或改用 probe 绕过；现有脚本没有套件内部的可选项豁免。

脚本模式：RUN 保存命令、退出码、日志、计数、环境与相关输入。相关文件/目录清单、任务标准、验证策略、开发规则、检查定义和执行器自身参与指纹。当前对整份 requirements、validation、agent_policy 文件散列，即使其中仅有与当前检查无关的文字变化也会失效；没有章节级或语义等价豁免。无关文件变化不自动使结果失效；映射遗漏依赖则程序无法发现，开发 AI 在接入或修改检查时须对照实际读取的代码、资源和配置及相关生成关系核对输入映射。

每次执行所需的环境观察应与该次命令、起止时间、退出码、日志位置和对象身份关联，复用现有RUN或任务记录。对影响结果的运行时/依赖，用实际执行进程的版本输出、加载路径或相应探针确认，不能以任务结束时的全局环境覆盖早期基线。脚本模式已有环境变量字段只保存选定值的哈希，不会自动发现已安装依赖版本；环境事实可写本次检查日志，需使后续依赖变化触发失效时，将实际锁文件/依赖身份文件加入inputs或映射适用的环境变量。缺少观察保留缺口，不补造历史版本。

例如Node检查可在实际检查入口输出`process.version`；Electron检查应在实际Electron进程输出`process.versions.electron`及`process.versions.node`，分别标明开发Node与内置Node。项目自行选择必要的非敏感字段，不转储完整环境变量或令牌。只有日志中的版本事实而未映射相关输入时，复用仍需人工核对环境变化。文档模式沿现有命令和日志保留这些关联，不要求新增JSON协议或切换模式。

需要反复核对Git对象清单时，可选用[Git输入快照](cli.md#可选git输入快照)，也可用现有等效工具；它只保存清单与内容身份，不运行测试、不检查Markdown语义或自动判断证据有效。用选定对象的文件内容执行检查，并核对采证前后清单与交付对象；工作树测试通过不能只靠一份暂存快照变成暂存对象通过。

交付前核对验证对象与交付对象的对应关系。Git暂存内容、工作树、构建产物或运行实例可能不同；提交/打包前核对实际差异及相关输入，不能用另一个版本的通过证明待交付版本。可证明相关输入一致时复用证据，不要求为无关差异重跑。提交说明描述实际差异，日志或计划的修改不证明实现已经改变。

交付语义审阅按 [独立上下文复核](maintenance.md#独立上下文复核) 判断是否需要独立审阅及如何处置缺口；复核记录与本任务实际差异、证据对应。

多个工具衔接时，范围选择、实际执行、证据保存和交付判定须对应同一验证对象及相关输入；转换后的结果仍能追溯原始记录，不丢失失败、跳过、未结束或失效信息。验证期间对象或相关输入变化时重核证据，不能只核对最初的范围快照。输入映射遗漏与结果误译分别处理，不能用扩大测试范围替代修复衔接缺口。

文档模式复用项目现有执行结果并核对相同的证据边界，不要求生成 RUN。脚本模式每个检查取最近 RUN。最近失败、中断、运行中或损坏不复用旧通过。日志、摘要和测试报告校验和用于识别意外损坏；能够改写项目的主体仍可伪造全部文件，首版没有签名或独立保护服务。close 不保证真实用户语义，只说明所映射机械条件是否满足。

脚本模式人工验收 required 时在任务 human_acceptance[验收ID] 记录 status=accepted、source=真实确认来源、contract=当前任务标准指纹（close/resume 返回）。范围改变后确认重新核对。没有真实确认不能写 accepted，不能让产品内 AI 改自己的验收。

初次接入和修改机制时，按风险执行正反例：缺验收、漏检查、全跳过、坏回执、相关输入变化、执行中源码变化、超时、恢复，以及合法无关变化。可复用[随包自检](cli.md#可移植机制自检)覆盖其声明的共同边界；项目适配仍需自己的证据，不默认每轮业务修改都跑机制自检。数量和成功率不能单独证明长期效率。

实际 UI、音频、模型生成和数据恢复需要各自真实环境证据；离线夹具不代表新生成成功，工程完成不代表主观质量或发布授权。未启用并实测平台 hooks 时用 AI 主动执行，不宣称平台强制触发。Codex 显式配置验证与实际 UI 发现分开报告。
