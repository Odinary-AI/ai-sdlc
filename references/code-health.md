# 代码健康检查

执行、适用性、记录、通过条件与维护统一遵循 [maintenance.md](maintenance.md)；本文件维护专项检查维度。

输入：源码、生成源与生成物说明、变更历史、测试与调用入口、现有编码约定。阶段检查复用maintenance中的累积变化依据；相关条目结合既有发现、例外条件和前后变化判断，不以指标自动重构。

检查对象包括范围内业务源码、测试与辅助代码、构建脚本、依赖声明和配置。下列信号用于定位具体理解、修改或验证成本，不按参数数目、类型形式或信号数量自动要求重构；有依据的现有设计可以保留。数据与接口契约变化联查[设计完整性与一致性](design-conformance.md)，可测试性联查[验证健康](validation-health.md)，共用证据不重复登记。

## 批量修改保护

脚本结构修改或批量替换、迁移、生成前，明确预期文件与匹配范围，用预期匹配数量或等效结构断言核对；观察到的数量、结构或对象不符时，停止受影响修改并查明差异，不在未知匹配下继续写入。数量并非唯一方法，结构解析、明确对象清单等能约束同一范围的检查可以复用；不要求所有修改固定匹配一次。

执行后审查实际差异，核对零匹配、漏改及范围外误改，并按受影响契约验证。脚本退出成功和语法通过不能单独证明修改正确。保护适用于代码、配置与文档，不要求先启动正式专项；复用当前任务的必要差异与核对结果，不另建批量修改台账。

## 遗留与废弃物处置

检查不限于重构残留，也包括功能下线、试验与临时调试结束、迁移中断或实现演进造成的失效和孤立对象。按本次授权范围，从项目现行目标、有效入口、消费者及实际变化追查不再承担有效职责的代码和文件，包括不再可达的分支/函数、旧文件、依赖与资源、配置/开关、测试/样本、脚本及当前文档。来源仅帮助定位，不直接决定可删；仍在途或未完成的试验/迁移材料先核对现场和恢复需要。局部任务只查受影响关系，阶段代码健康检查结合累积变化检查遗留；用户可通过[遗留与废弃物治理入口](maintenance.md#遗留与废弃物治理入口)单独发起有界检查或清理，无需建立新台账。

静态搜索、分析器告警及覆盖率只用于定位候选。判定不再使用时，沿maintenance的否定取证规则核对导入/调用、动态加载与注册、配置、构建/打包和外部消费者，并结合兼容及保留承诺；没有文本引用或本轮测试未执行到，均不足以单独证明可删除。相关旧测试也可能保护仍有效的失败、兼容或回归行为，不能因实现换新就退役。

先按[删除与移动的授权边界](project-layout.md#删除与移动的授权边界)核对具体授权；确认废弃且属于授权范围的可逆对象主动删除或合并，同步有效消费者，保留相应恢复依据；仍有兼容、恢复、历史或审计用途的说明理由保留。暂不能判定的说明缺少的依据、暂留原因和复查条件，沿既有任务/待办记录，不阻塞独立可处理项；当前验收依赖的疑点须补齐，不能转待办后宣称完成。历史证据与用户数据沿各自保留规则，不以“旧”认定废弃；缓存和生成物沿[目录清理入口](project-layout.md#目录检查与清理入口)处置。

清理后沿CH-06核对实际差异、预期退役对象及相关消费者的真实行为，验证力度按受影响范围选择。文件数或行数下降、检索无匹配和测试通过，都不能单独证明所有残留已清除；完成结论只覆盖实际调查和处置范围，不设“零残留”或删除数量目标。
